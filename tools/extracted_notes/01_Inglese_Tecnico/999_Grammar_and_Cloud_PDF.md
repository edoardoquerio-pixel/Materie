Here are the most common grammar features you’ll see in the cloud computing / 
cloud systems sector, especially in docs, specs, tickets, and technical 
communication. 

Key structure 

Function 

Passive 

Used when the focus is on the system, 
process, or data, not the person. 

Modal Verbs 

Used in requirements, configurations, 
and policies. 

Conditional Sentences (If-clauses) 

Used for system behavior, 
troubleshooting, automation. 

Imperatives 

Very common in guides, CLI usage, and 
procedures. 

Noun Stacking (Compound Nouns) 

Multiple nouns used together as 
adjectives. 

Present Simple 

Used to describe how systems 
generally work. 

Future 

Will (automatic results) - Going to 
(planned actions). 

Relative Clauses 

Used to explain components and 
services.

Ex. 5 - Noun Stacking (Compound Nouns) 

Before starting: 

What it is: 

Noun stacking happens when two or more nouns are placed together to act as a 
single noun phrase. 
In English, this is very common in technical writing because it compresses 
information into short, precise expressions. 

Structure: 

[Noun] + [Noun] (+ [Noun] …) 

● The first noun(s) describe or modify the last noun, which is the main object. 
● The last noun is the head of the phrase, the “main thing.” 
● No articles (“a / the”) are usually used between nouns. 

Examples: Data Storage system; Cloud security policy. 

How to read them: 

1. Start from the rightmost noun → main thing. 
2. Each noun to the left modifies the main noun. 
3. Often used to make technical writing concise. 

Example: 

● CONTAINER ORCHESTRATION TOOL → a tool (main noun) for 

orchestrating containers. 

Tips 

● Too long? If there are 4+ nouns, consider using “of” for clarity: 

○ cloud infrastructure provider service → service of a 

cloud infrastructure provider 
● Plural nouns usually appear only at the end: 
○ Correct: API request limit 
○ Avoid: APIs request limit 

 
 
 
 
 
How to order nouns in a stack 

Rule of Thumb: 

1. The rightmost noun is the main noun – the “thing” you are talking about. 
2. Nouns to the left act as adjectives – they describe or limit the main noun. 
3. Order modifiers from general → specific: the first noun is more general, 

the one closer to the main noun is more specific. 

Step-by-Step Example 

Words: cloud / security / policy 

1. Identify the main noun → What is the “thing”? 
○ policy → yes, the main object. 

2. Decide which noun is more general / which is more specific: 
○ cloud → general context (applies to cloud systems) 
○ security → specific aspect (focuses on security) 

3. Arrange general → specific → main noun: 

○ cloud security policy ✅ 

Another Example: application / deployment / pipeline 

1. Main noun → pipeline (it’s the thing) 
2. What describes the pipeline? → deployment (type of pipeline) 
3. More general context → application (what is being deployed) 
4. Stack: application deployment pipeline ✅ 

Quick Tips 

1. Think: “Which noun answers the question ‘what kind of …?’” 

○ What kind of pipeline? → deployment 
○ What kind of deployment pipeline? → application 

2. Context matters – sometimes you reorder for clarity: 

○ database backup solution → solution for backing up databases 
○ backup database solution ❌ sounds odd 

3. Optional adjectives: 

Sometimes a noun can act like a regular adjective: 

 
 
 
 
○ server performance monitoring → monitoring (main) of server 

performance (modifiers) 

4. Practice makes perfect – start by identifying main noun → most specific 

modifier → more general modifier.
